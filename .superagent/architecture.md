# معماری داده و انتخاب دیتابیس برای دستیار هوشمند ترب (Database & Agent Architecture)

## ۱. صورت مسئله و مأموریت انتخاب دیتابیس
هدف، انتخاب و طراحی پایگاه داده‌ای است که بتواند به یک **عامل هوش مصنوعی (AI Agent)** بالاترین دقت، سرعت زیر ۵ میلی‌ثانیه، عدم توهم (Zero Hallucination)، و ساده‌ترین فرآیند دیپلوی پایدار (کسب ۴۰ امتیاز دیپلوی) را ارائه دهد.

## ۳. تصمیم قطعی: معماری هیبریدی SQLite با ایندکس چندبعدی

### چرا SQLite + FTS5 بهترین انتخاب بی‌رقیب است؟
1. **حجم کل داده‌ها**: حجم فایل‌های متنی فشرده‌نشده حدود ۲۸۵ مگابایت است. این حجم در ساختار ایندکس‌شده SQLite به حدود **۱۸۰ مگابایت** می‌رسد. کل این پایگاه داده در حافظه رم سیستم کش می‌شود و سرعت پاسخگویی آن زیر ۵ میلی‌ثانیه است.
2. **پشتیبانی کامل از ساختارهای موجود**:
   - ستون‌های JSON (`specs`, `weekly_hours`, `payment_options`) با ماژول بومی `json1` در SQLite بدون نیاز به تغییر اسکیمای پیچیده پشتیبانی می‌شوند.
   - ماژول `fts5` با توکنایزر یونیکد امکان جستجوی کامل عبارات فارسی، کدهای پارت‌نامبر و اسامی برندها را فراهم می‌کند.
3. **صفر درصد ریسک در دیپلوی**: پایگاه داده در قالب یک فایل `torob.db` کنار کد پروژه قرار می‌گیرد؛ بدون نیاز به تنظیم Docker-compose دیتابیس، بدون نیاز به باز کردن پورت‌های ۵۴۳۲ یا ۹۲۰۰، و بدون کرش‌های حافظه (OOM).

## ۴. استراتژی «صفر اشتباه» ایجنت (Zero-Error / Hallucination-Proof Protocol)

بزرگ‌ترین خطر شکست ایجنت‌ها در اتصال به پایگاه داده، استفاده از الگوی **Text-to-SQL آزاد** است (که در آن مدل زبانی خودش کوئری SQL بنویسد). با توجه به اینکه در دیتای ترب فیلد `model` در ۹۸٪ و `brand_name` در ۷۴٪ موارد null است و ۲۶۸۴ مغازه هیچ آفری ندارند، نوشتن مستقیم SQL توسط LLM منجر به نتایج خالی یا اشتباه فاحش می‌شود.

### راهکار معماری: الگو ابزارهای ساختاریافته و قطعی (Deterministic Domain Tools)
مدل زبانی فقط به عنوان **استخراج‌کننده نیت (Intent Extractor)** عمل می‌کند و توابع زیر را فراخوانی می‌کند:

```
┌────────────────────────────────────────────────────────┐
│ ورودی کاربر: "یک لپ‌تاپ ایسوس تا ۵۰ تومن حوالی چارسو" │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ ایجنت هوشمند (LLM / Function Calling):                 │
│ Call: search_products(q='لپ تاپ ایسوس', max_p=50000000)│
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ لایه منطق دامنه (Domain Hardened Logic in SQLite):      │
│ • نرمال‌سازی حروف فارسی (ی/ک/فاصله‌ها)                   │
│ • جستجوی FTS5 روی persian_title و specs                 │
│ • فیلتر آفرها: حذف قیمت‌های null و نامتعارف             │
│ • فیلتر فروشگاه‌ها: حذف فروشگاه‌های فاقد آفر           │
│ • اعتبارسنجی ساعات کاری (آیا الان باز است؟)             │
│ • محاسبه فاصله جغرافیایی تا چارسو                      │
│ • محاسبه شاخص تازگی قیمت (Freshness Score)             │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ خروجی ساختاریافته و ۱۰۰٪ بدون توهم جهت ارائه به کاربر  │
└────────────────────────────────────────────────────────┘
```

### توابع ۴ گانه ابزارهای ایجنت:
1. `search_products(query, category, min_price, max_price, limit)`: جستجوی متنی فارسی دقیق با FTS5.
2. `get_store_offers(product_id, lat, lon, max_distance_km, neighborhood, mall_name, open_now, is_torobpay)`: استخراج فروشگاه‌های دارای کالا با فیلتر ساعت کاری، روش پرداخت و گارانتی.
3. `get_mall_fallbacks(mall_name, product_id, category)`: یافتن مغازه‌های جایگزین در همان پاساژ و طبقه در صورت عدم موجودی.
4. `generate_visit_dossier(shop_id, product_id)`: ساخت پرونده کامل مراجعه با پلاک، طبقه، تلفن و چک‌لیست تست حضوری.
